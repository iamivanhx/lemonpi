# Pi footer and usage-display alternatives (Pi 1.4.0)

## Summary

**Finding:** Keep/replace is a layout-versus-quota trade-off, not a clear upgrade. `pi-footer` v0.5.1 alone reproduces Ivan's eight widgets but does not query subscription limits; `@narumitw/pi-usage` can add Codex quota/reset through Pi's status API, not Claude Code CLI quota. `@djoeyg/pi-usage` reads both CLI logins and publishes a status, but is newer/smaller and shares conflicting `/usage`, status key and config filename with narumitw. Pi 1.4.0's built-in footer has session cost and extension status but no quota/reset or Ivan's one-line layout. `pi-footer` appends statuses as an extra line by default; a status widget plus hidden aggregate key may keep one line, untested. [pi-footer v0.5.1 source](https://github.com/wobondar/pi-footer/blob/main/src/index.ts), [narumitw source](https://github.com/narumiruna/pi-extensions/blob/main/packages/pi-usage/src/usage.ts), [djoeyg source](https://github.com/D-Joey-G/pi-extensions/blob/main/packages/pi-usage/index.ts), [Pi 1.4 footer](https://github.com/earendil-works/pi/blob/v1.4.0/packages/coding-agent/src/modes/interactive/components/footer.ts).

## Candidate capabilities and configuration

Ivan's existing `~/.pi/agent/extensions/pi-footer.json` (read-only inspection, 2026-10-26) specifies one row of eight widgets: raw git-root, branch, raw context-bar, raw session cost (`showSubscription:false`), insertions, deletions, model, thinking; `extensionStatusRow` has empty `knownKeys`/`hiddenKeys`. This is a local observation, not an upstream source. [pi-footer README (main, accessed 2026-10-26)](https://github.com/wobondar/pi-footer#readme) documents the same widget types, a configurable `Pi Extension Status` widget for `ctx.ui.setStatus`, `/footer`, presets, and file `~/.pi/agent/extensions/pi-footer.json` (or `PI_FOOTER_CONFIG`). Its cost widget is estimated cost, **not** plan quota or reset time. Its configurable git-insertions/deletions, context bar, model, thinking make it the only *verified exact layout* so far. [README widgets](https://github.com/wobondar/pi-footer#widgets).

Config: `<agentDir>/pi-usage.json`, including `statuslineDisplay`, `codexStatusPercentage`, `codexStatusResetCountdown`; refresh five minutes. Its [provider reference](https://github.com/narumiruna/pi-extensions/blob/main/packages/pi-usage/docs/providers.md) lists `openai-codex` and native `openai`, **not** `claude-code` or `anthropic`: it does not provide Ivan's Claude CLI quota. Native `openai` needs explicit same-account companion `openai-codex` login opt-in, otherwise web-only guidance; not relevant if Ivan stays with `openai-codex`. [README auth/companion](https://github.com/narumiruna/pi-extensions/blob/main/packages/pi-usage/README.md#chatgpt-companion-usage).

[`@djoeyg/pi-usage`](https://github.com/D-Joey-G/pi-extensions/blob/main/packages/pi-usage/README.md) gives `/usage` overlay (Claude/Codex/OpenCode Go, remaining % and resets) and one combined `usage` status with active model first; [source](https://github.com/D-Joey-G/pi-extensions/blob/main/packages/pi-usage/index.ts) recognizes provider ID matching `/claude|anthropic/`, including `claude-code`, reads Claude Code's macOS Keychain item `Claude Code-credentials` or `~/.claude/.credentials.json`, and Codex CLI `~/.codex/auth.json`; **credentials read-only and not refreshed**. ## Coexistence, compatibility, maintenance

**Answer to coexistence:** `@narumitw/pi-usage` publishes `ctx.ui.setStatus("usage", value)` ([source `usage.ts`, main accessed 2026-10-26](https://github.com/narumiruna/pi-extensions/blob/main/packages/pi-usage/src/usage.ts)); pi-footer v0.5.1 reads the Pi footer status map and appends **one additional row** of all nonhidden status values ([render code](https://github.com/wobondar/pi-footer/blob/main/src/index.ts), [filter](https://github.com/wobondar/pi-footer/blob/main/src/extension-statuses.ts)). The local empty `hiddenKeys` means usage would appear in a *second line* when available. To preserve a **single line**, add an `external-status`/Pi Extension Status widget with `options.externalStatusKey:"usage"` into `lines[0]` and add `"usage"` to `extensionStatusRow.hiddenKeys` to avoid duplicating it in the appended row; this is an inference from the [widget implementation](https://github.com/wobondar/pi-footer/blob/main/src/widgets/core/external-status.ts) and [status row implementation](https://github.com/wobondar/pi-footer/blob/main/src/index.ts), **not runtime-tested**. Other extensions' published statuses can still create a second row unless hidden. `knownKeys` is a UI selection history, not an allowlist ([source](https://github.com/wobondar/pi-footer/blob/main/src/extension-statuses.ts)). No second `setFooter` is needed for quota-only publishers. [Pi 1.4.0 API example](https://github.com/earendil-works/pi/blob/v1.4.0/packages/coding-agent/examples/extensions/custom-footer.ts).

Pi 1.4.0's [built-in footer code](https://github.com/earendil-works/pi/blob/v1.4.0/packages/coding-agent/src/modes/interactive/components/footer.ts) renders path/branch/session name; input/output/cache tokens, hit rate, session estimated cost with subscription marker, context percentage/window, model/provider (if room) and thinking. It reads and displays extension status texts from its [footer-data provider](https://github.com/earendil-works/pi/blob/v1.4.0/packages/coding-agent/src/core/footer-data-provider.ts). It does **not** itself query provider subscription quotas/reset times or show git insertion/deletion counts or Ivan's context bar; those require extensions. Pi [TUI docs at v1.4.0](https://github.com/earendil-works/pi/blob/v1.4.0/packages/coding-agent/docs/tui.md) distinguish `ctx.ui.setStatus()` (additive), `setWidget()` (near editor), and `setFooter()` (replacement). Therefore simultaneous replacement footers compete for one slot. `pi-footer` owns only `setFooter`, whereas [pi-pretty source](https://github.com/heyhuynhgiabuu/pi-pretty/blob/main/src/index.ts) installs a custom *editor* and tool renderers: distinct seams, though combined runtime unverified. `pi-powerline-footer` also [calls `setEditorComponent` and `setFooter`](https://github.com/nicobailon/pi-powerline-footer/blob/main/index.ts), so unlike pi-footer it **may compete with pi-pretty for editor ownership**; its README [describes partial autocomplete-wrapper composition, not full editor composition](https://github.com/nicobailon/pi-powerline-footer#editor-autocomplete-composition). Do not assume load order solves this. pi-pretty source link is current main, **not** a test of Ivan's previously cataloged pinned 0.6.29 version ([prior catalog](pi-package-catalog.md#existing-packages-and-pending-decisions)).

**Options (trade-offs, no selection):**

1. **Keep pi-footer alone:** exact current one-line layout, no actual subscription quota/reset; its cost is an estimated dollar figure ([pi-footer widgets](https://github.com/wobondar/pi-footer#widgets)).
2. **Keep + `@narumitw/pi-usage`:** mature repo and Codex quota/reset, no Claude CLI. Default published `usage` becomes **another footer row**; insert an `external-status` widget and hide `usage` from aggregate row to attempt a one-line layout ([pi-footer source](https://github.com/wobondar/pi-footer/blob/main/src/index.ts), [pi-usage source](https://github.com/narumiruna/pi-extensions/blob/main/packages/pi-usage/src/usage.ts)).
3. **Keep + `@djoeyg/pi-usage`:** one additive status for both CLI accounts and `/usage` overlay, but smaller/younger repo; read-only CLI tokens may expire until CLI refresh. It is an *alternative*, not a companion, to narumitw because `/usage`, `usage` status, and `pi-usage.json` overlap ([source](https://github.com/D-Joey-G/pi-extensions/blob/main/packages/pi-usage/index.ts)).
4. **Replace with pi-minimal-footer, pi-minimal-statusbar, powerline, or another replacement:** trade exact layout (and sometimes non-footer features) for built-in quota or a different display. Claude Code auth remains unverified for the replacement's own quota code; a dedicated CLI-compatible status publisher can be combined if it doesn't call `setFooter` ([sources in table](https://pi.dev/packages?name=footer)).

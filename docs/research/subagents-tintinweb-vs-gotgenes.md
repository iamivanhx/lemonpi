# Tintinweb vs gotgenes subagents for Ivan (Pi 1.4.0)

## Summary

Both supply in-process foreground/background delegation, three built-in agent types, custom Markdown agents, resume and steering. **The five current files can be discovered by gotgenes at their present global paths, but are not behaviorally drop-in**: gotgenes ignores `name:` (filenames happen to agree), changes prompt inheritance and caller-override defaults, and treats extension-tool names differently. The largest integration difference is that gotgenes announces child sessions to the permission system before binding extensions; tintinweb 0.22.0 does not, so permission prompts inside its children have **no guaranteed parent forwarding**. Tintinweb includes scripted workflows, nested agents, scheduler, skill preloading, and worktree flags; gotgenes offers ask-back/notify-parent, a typed service and native permission lifecycle, with worktrees as an extra package. None of this is an end-to-end Pi 1.4 test. [Tintinweb 0.22.0 README](https://github.com/tintinweb/pi-subagents/blob/v0.22.0/README.md), [gotgenes 25.0.4 README](https://github.com/gotgenes/pi-packages/blob/pi-subagents-v25.0.4/packages/pi-subagents/README.md), [gotgenes comparison (historical versions; do not use its table as current fact)](https://github.com/gotgenes/pi-packages/blob/pi-subagents-v25.0.4/packages/pi-subagents/docs/comparison-with-upstream.md).

## Custom agent definitions and Ivan's files

**Tintinweb 0.22.0:** reads `<cwd>/.pi/agents/*.md` > `<cwd>/.agents/agents/*.md` > `$PI_CODING_AGENT_DIR/agents/*.md` (default `~/.pi/agent/agents`) > pi-package-declared agents. `name:` defines dispatch identity, otherwise basename; body is system instructions. Fields include `description`, `display_name`, `color`, `tools`, `extensions`, `exclude_extensions`, `skills`, `disallowed_tools`, `memory`, `isolation`, `model`, `thinking`, `max_turns`, `prompt_mode`, `inherit_context`, `run_in_background`, `isolated`, `allowed_subagents`, `persist_session`, `output_transcript`, `session_dir`, `enabled`. Default custom `prompt_mode` is **replace**; set model/thinking/etc. in frontmatter and they override the `Agent` caller. `tools` names seven built-ins, with `ext:<extension>/<tool>` for extension tools; default all built-ins. `skills: true` inherits skills, `false` disables, a list preloads only named skills. [`README § Custom Agents / Tool & extension scoping / Skill Preloading`](https://github.com/tintinweb/pi-subagents/blob/v0.22.0/README.md#custom-agents), [published loader](https://github.com/tintinweb/pi-subagents/blob/v0.22.0/src/custom-agents.ts).

**Gotgenes 25.0.4:** reads `<cwd>/.pi/agents/*.md` > `$PI_CODING_AGENT_DIR/agents/*.md`; **filename** defines dispatch identity; `name:` is not read by the loader. Body is instructions; `prompt_mode` defaults to **append** (parent's identity is base); `replace` appends the specialist instruction last without the wrapper, rather than tintinweb's standalone replace. Supported fields: `description`, `display_name`, `tools`, `model`, `thinking`, `max_turns`, `prompt_mode`, `inherit_context`, `run_in_background`, `enabled`, `locked`. `tools:` is the full allowlist (seven built-ins plus any extension-registered names); accepts comma string, flow YAML list, or block YAML list; no `ext:` namespace. Omitting tools exposes built-ins only. `locked: true` locks set invocation fields, or specify a lock list; otherwise call parameters override model/thinking/max_turns/context/background defaults. The core has **no** per-agent `skills:`, `extensions:`, `disallowed_tools:`, `memory:`, `isolated:`, or `isolation:` fields; children inherit parent skills and extensions by default, with package-wide extension exclusions in `subagents.json`. `permission:` is read by the **separate** permission-system extension, not the subagents loader. [`configuration § Custom Agents / Tool selection / Excluding package extensions`](https://github.com/gotgenes/pi-packages/blob/pi-subagents-v25.0.4/packages/pi-subagents/docs/configuration.md#custom-agents), [loader](https://github.com/gotgenes/pi-packages/blob/pi-subagents-v25.0.4/packages/pi-subagents/src/config/custom-agents.ts), [permission adapter § two layers](https://github.com/gotgenes/pi-packages/blob/pi-permission-system-v41.0.0/packages/pi-permission-system/docs/subagent-integration.md#coexistence-with-other-subagent-extensions).

**Observed local files** (`~/.pi/agent/agents/{explorer,implementer,merger,researcher,reviewer}.md`, read 2026-10-26 UTC): each declares `name:` equal to filename, `description`, `model`, `thinking`, and YAML-block `tools:`. Explorer and reviewer use `read, grep, find`; implementer `read, grep, find, edit, write, bash`; merger `read, grep, find, bash`; researcher has the implementer set **plus `mcp`, `mcpScript`**. All have instruction bodies and no `skills:`, `prompt_mode:`, `permission:`, `locked:`, or `isolation:`. The block-list syntax is expressly supported by gotgenes. Under gotgenes all five are discovered and their normal built-in tool names/model/thinking/description/body can be parsed; whether their model IDs are available in Ivan's configured model registry was not checked. [Gotgenes loader](https://github.com/gotgenes/pi-packages/blob/pi-subagents-v25.0.4/packages/pi-subagents/src/config/custom-agents.ts), [configuration § Tool selection](https://github.com/gotgenes/pi-packages/blob/pi-subagents-v25.0.4/packages/pi-subagents/docs/configuration.md#tool-selection).

**Incompatibilities/behavior to review before calling them unchanged:** (1) `name:` is silently ignored by gotgenes; these five coincide with filename, so *no dispatch-name break today* but renaming a file would change its type. (2) Without `prompt_mode: replace`, the inherited parent identity is wrapped in, rather than tintinweb's default standalone custom-agent prompt; even explicitly setting replace does not make the two implementations' inheritance identical. (3) Gotgenes allows `subagent({model,thinking})` to override file pins unless `locked: true` or `locked: model, thinking` is added; tintinweb's file pins take precedence. (4) `mcp`/`mcpScript` in **researcher** are not among either package's seven built-ins: tintinweb diagnoses plain unknown built-in names (its extension syntax is `ext:…`); gotgenes grants them **only if** some loaded extension actually registers tools with those exact names. Their actual registration/availability in Ivan's Pi 1.4 stack was not established; do not assume migration creates or removes working MCP access. (5) Any *future* tintinweb-only frontmatter (skills, extension scoping, nested agents, worktree, memory, denylist) would not carry across. Existing five do **not** use those keys. Existing instruction bodies refer to a parent-supplied worktree/branch and a handoff contract; neither package automatically assigns a worktree from these files. [Tintinweb loader / known-tool warning](https://github.com/tintinweb/pi-subagents/blob/v0.22.0/src/agent-runner.ts), [gotgenes loader](https://github.com/gotgenes/pi-packages/blob/pi-subagents-v25.0.4/packages/pi-subagents/src/config/custom-agents.ts), [gotgenes configuration](https://github.com/gotgenes/pi-packages/blob/pi-subagents-v25.0.4/packages/pi-subagents/docs/configuration.md#frontmatter-fields), [local files as read above].

## Built-ins and overrides

Both embed `general-purpose` (all built-ins, parent twin), `Explore` (read, bash, grep, find, ls; Haiku if available), and `Plan` (same read/search tools, parent model). Custom files of the same name override; `enabled: false` can disable one per project. Tintinweb additionally offers `/agents` Eject and a global/project `disableDefaultAgents` setting that removes all three built-ins; gotgenes documents per-file disabling, **not** that setting. Gotgenes currently pins Explore to `anthropic/claude-haiku-4-5-20251001`, tintinweb specifies `anthropic/claude-haiku-4-5`; both resolve/fall back according to availability. [`Tintinweb default-agents.ts`](https://github.com/tintinweb/pi-subagents/blob/v0.22.0/src/default-agents.ts), [`Tintinweb README § Disable defaults`](https://github.com/tintinweb/pi-subagents/blob/v0.22.0/README.md#persistent-settings), [`gotgenes default-agents.ts`](https://github.com/gotgenes/pi-packages/blob/pi-subagents-v25.0.4/packages/pi-subagents/src/config/default-agents.ts), [`gotgenes config § defaults`](https://github.com/gotgenes/pi-packages/blob/pi-subagents-v25.0.4/packages/pi-subagents/docs/configuration.md#default-agent-types).

## Orchestration

**Shared:** foreground calls block, background calls return an ID and notify on finish; `get_subagent_result`, `steer_subagent`, resume by ID, context inheritance, fuzzy models, live UI and background concurrency queues. **Different tool names/arguments:** tintinweb `Agent({subagent_type,prompt,description,run_in_background,resume,...})` plus `SubagentWorkflow`; gotgenes `subagent({...})` plus `get_subagent_result` / `steer_subagent`; hard-coded `Agent` prompts/skill instructions must change. Tintinweb defaults unspecified top-level calls to **background** (`backgroundByDefault: true`); gotgenes defaults to **foreground** (`run_in_background: false`); explicit call flags avoid this change. Default concurrent background slots: tintinweb **10**, gotgenes **4**. Tintinweb has separate optional foreground concurrency bound and workflow-specific fanout; gotgenes foreground calls bypass the background queue. [Tintinweb README § Tools / Concurrency / Persistent Settings](https://github.com/tintinweb/pi-subagents/blob/v0.22.0/README.md#tools), [gotgenes README § Tools / Concurrency](https://github.com/gotgenes/pi-packages/blob/pi-subagents-v25.0.4/packages/pi-subagents/README.md#tools), [gotgenes configuration § settings](https://github.com/gotgenes/pi-packages/blob/pi-subagents-v25.0.4/packages/pi-subagents/docs/configuration.md#persistent-settings).

**Tintinweb-only in the compared core:** `SubagentWorkflow` runs scripted JS with `agent()` phases and replay/saved workflows; scheduler (cron/interval/one-shot); `@agent` mentions; opt-in nested delegation; built-in `isolation: worktree` flag/frontmatter; skill preloading, per-agent memory and extension scoping; model-scope setting and cross-extension event RPC; selectable group-join notifications; `/agents` management; `ctrl+b` foreground-to-background handoff. [Tintinweb README § Features / SubagentWorkflow / Scheduling / Nested subagents / Worktree](https://github.com/tintinweb/pi-subagents/blob/v0.22.0/README.md#features). **Gotgenes-only in the compared core:** child's `ask_parent` (ask a question then wait for resume) and `notify_parent` (mid-run updates); typed `SubagentsService` API; pre-bind child lifecycle announcements and `<active_agent>` tag consumed by its permission companion; hard turn ceiling with advance wrap-up warning rather than tintinweb's soft cap plus grace. Gotgenes has `/subagents:sessions` and `/subagents:settings`; no built-in scripted workflows, scheduler or per-call worktree flag. Separate [`@gotgenes/pi-subagents-worktrees`](https://github.com/gotgenes/pi-packages/blob/main/packages/pi-subagents-worktrees/README.md) provides **per-agent-type opt-in** worktrees (must load after core), not tintinweb's per-call `isolation`. [Gotgenes README § Features / Worktree Isolation / Removed features](https://github.com/gotgenes/pi-packages/blob/pi-subagents-v25.0.4/packages/pi-subagents/README.md#features), [configuration § tool selection](https://github.com/gotgenes/pi-packages/blob/pi-subagents-v25.0.4/packages/pi-subagents/docs/configuration.md#tool-selection). The gotgenes [comparison page](https://github.com/gotgenes/pi-packages/blob/pi-subagents-v25.0.4/packages/pi-subagents/docs/comparison-with-upstream.md) expressly compares **old 16.2.1 vs 0.10.3** and omits newer tintinweb features; the above uses current version docs/source instead.

## Permission integration

[Permission-system v41.0.0 adapter spec](https://github.com/gotgenes/pi-packages/blob/pi-permission-system-v41.0.0/packages/pi-permission-system/docs/subagent-integration.md#the-subagent-adapter-convention) requires **in-process** `subagents:child:session-created` *synchronously before* `bindExtensions()` and `subagents:child:disposed` (optional `bound` after binding) or, for subprocess children, `PI_SUBAGENT_PARENT_SESSION=<parent-id>` at spawn. Gotgenes v25.0.4 [publishes created before bind, bound afterward](https://github.com/gotgenes/pi-packages/blob/pi-subagents-v25.0.4/packages/pi-subagents/src/lifecycle/create-subagent-session.ts) and [disposed on teardown](https://github.com/gotgenes/pi-packages/blob/pi-subagents-v25.0.4/packages/pi-subagents/src/lifecycle/subagent-session.ts), with the [channels declared here](https://github.com/gotgenes/pi-packages/blob/pi-subagents-v25.0.4/packages/pi-subagents/src/lifecycle/child-lifecycle.ts).

**Source check of installed tintinweb 0.22.0:** [`src/agent-runner.ts`](https://github.com/tintinweb/pi-subagents/blob/v0.22.0/src/agent-runner.ts) creates its in-process session and calls `bindExtensions()` without the required child announcements; [`src/index.ts`](https://github.com/tintinweb/pi-subagents/blob/v0.22.0/src/index.ts) emits task-level `subagents:started/completed/failed` etc., **not** `subagents:child:session-created/disposed/bound`; a search across the packaged `src/` found no `PI_SUBAGENT_PARENT_SESSION` assignment (and this is not a subprocess architecture). This agrees with the adapter's [known-implementations matrix](https://github.com/gotgenes/pi-packages/blob/pi-permission-system-v41.0.0/packages/pi-permission-system/docs/subagent-integration.md#conformance-of-known-implementations). Task-level events are **not** sufficient to register a child before binding.

**Consequences, carefully qualified:** If the permission extension loads inside a tintinweb child, its own `tool_call` policy can still gate that child's visible tools; the lack of lifecycle announcements does **not by itself** imply all calls bypass checks. But child detection/parent target is not deterministic, so `ask` is **not guaranteed to forward** to Ivan's parent UI. [Authorizer selection](https://github.com/gotgenes/pi-packages/blob/pi-permission-system-v41.0.0/packages/pi-permission-system/src/authority/authorizer.ts) chooses local dialog with UI and no live relay target, parent relay when a detected headless child can resolve a parent, and denying authorizer when neither applies; absent a target, a forwarded ask fails unavailable rather than auto-approving. Actual UI/detection/heuristic behavior for tintinweb sessions was not run; therefore **do not assert every ask is silently denied**. Conversely, if the child does **not** load the permission extension (e.g. extensions disabled/excluded), it has no permission tool gate and its allowed tools run without that policy; tintinweb's `tools:` allowlist still restricts availability. Gotgenes' optional `bound` event enables the permission system to warn about such unguarded children, whereas tintinweb cannot supply that alarm. [Permission adapter § What this package does / loading asymmetry](https://github.com/gotgenes/pi-packages/blob/pi-permission-system-v41.0.0/packages/pi-permission-system/docs/subagent-integration.md#what-this-package-does-on-both-ends), [gotgenes configuration § excluding permission extension](https://github.com/gotgenes/pi-packages/blob/pi-subagents-v25.0.4/packages/pi-subagents/docs/configuration.md#excluding-a-permission-extension), [tintinweb runner](https://github.com/tintinweb/pi-subagents/blob/v0.22.0/src/agent-runner.ts). Neither package is a security sandbox. The permission-system's `permission:` per-agent frontmatter uses an `<active_agent>` system-prompt tag; **both packages emit that tag** in child prompts, so the frontmatter name can be available even when tintinweb's child lifecycle/parent-forwarding contract is missing. Whether the permission extension actually loads and applies it in Ivan's child remains untested. [Tintinweb prompts source](https://github.com/tintinweb/pi-subagents/blob/v0.22.0/src/prompts.ts), [gotgenes prompts source](https://github.com/gotgenes/pi-packages/blob/pi-subagents-v25.0.4/packages/pi-subagents/src/session/prompts.ts), [adapter § per-agent policy](https://github.com/gotgenes/pi-packages/blob/pi-permission-system-v41.0.0/packages/pi-permission-system/docs/subagent-integration.md#what-this-package-does-on-both-ends).

## Migration cost for Ivan

**One installer swap is not the whole migration.** Replace package spec and any `Agent(...)` references in lemonpi-owned prompts/skills with `subagent(...)`, review default foreground-vs-background and 10-vs-4 concurrency, move settings only by translating keys (both use `subagents.json`, but not identical schemas), and do not load two competing subagent extensions by default. Keep the five Markdown files in the same global location initially; if preserving their current model/thinking pins matters, add `locked: model, thinking`; explicitly consider prompt inheritance (`prompt_mode`) and verify actual `mcp`/`mcpScript` registration. Researcher/implementer/merger worktree handoff remains an orchestration requirement: either parent supplies a worktree as today or add and configure the separate gotgenes worktrees package; its per-agent-type selection is not a per-call equivalent. Replace any workflows/scheduling, nested delegation, memory, preloaded skill behavior or `/agents` interaction **only if Ivan actually uses it**; none is declared in his five files. The benefit to validate is permission forwarding with child extension loaded; check both `ask` and `deny` in an isolated Pi 1.4 trial, not merely peer satisfaction. ## Side-by-side

| Aspect | `@tintinweb/pi-subagents` 0.22.0 | `@gotgenes/pi-subagents` 25.0.4 |
|---|---|---|
| Agent files | `.pi/agents`, `.agents/agents`, global, package declarations; `name:` identity | `.pi/agents`, global; **filename** identity |
| Five existing files | Same source format; `mcp`/`mcpScript` plain names warn as unknown built-ins | Discoverable; `name:` ignored (same basenames), changed prompt/pin precedence; `mcp`/`mcpScript` need exact registered extension tools |
| Built-ins | `general-purpose`, `Explore`, `Plan`; override/disable; all-off setting | Same three; override/disable via files |
| Spawn / default mode | `Agent`; background unless specified | `subagent`; foreground unless specified |
| Concurrent background | 10 default | 4 default |
| Resume / steer | Both, `get_subagent_result`, `steer_subagent` | Both, same result/steer names; adds `ask_parent`/`notify_parent` |
| Isolation | Built-in per-call/per-agent worktree | Companion worktrees package, opt-in per agent type |
| Scripted workflows / schedule | Built-in `SubagentWorkflow` / scheduler | Neither in core |
| Skills / nesting | Per-agent preloading, optional nested agents | Parent skills inherited, no per-agent preload or child nested spawn |
| Permission lifecycle | No adapter child broadcasts; ask-forwarding not deterministic | Pre-bind created, disposed, optional bound; native adapter contract |
| Compatibility evidence | Pi peer >=1.1; runtime not tested | Pi peer >=1.0; runtime not tested |

Table sources: [tintinweb README and published source](https://github.com/tintinweb/pi-subagents/tree/v0.22.0), [gotgenes 25.0.4 docs and source](https://github.com/gotgenes/pi-packages/tree/pi-subagents-v25.0.4/packages/pi-subagents), [permission adapter v41.0.0](https://github.com/gotgenes/pi-packages/blob/pi-permission-system-v41.0.0/packages/pi-permission-system/docs/subagent-integration.md).

## What this means for the choice

Tintinweb preserves the all-in-one orchestration surface and frontmatter semantics; gotgenes is a smaller core plus optional companions, with a documented permission-child contract and explicit ask-back/update channel. For Ivan the five files are **portable as readable definitions, not behaviorally identical**, and migration means auditing the calling instructions and testing permission/UI/MCP and worktree behavior. Choosing whether native permission forwarding outweighs tintinweb workflows and caller/file semantics is a product decision, not established by this research. [Source references above](#side-by-side).

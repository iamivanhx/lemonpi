# pi-permission-system research (issue #4)

## Summary

As of npm release **41.0.0** (registry lookup 2026-10-25), this is a configurable Pi **permission gate, not a sandbox**. Its `external_directory` scope means outside **session cwd**, not outside a Git working tree. Project and per-agent rules can override global rules in trusted projects. Its native subagent integration is `@gotgenes/pi-subagents`, **not** the planned `@tintinweb/pi-subagents`; the latter does not announce children for automatic forwarding. Bash uses tree-sitter and floors unknown/opaque cases to `ask`, but text patterns cannot certify that an ordinary `git push` is non-destructive. [Configuration](https://github.com/gotgenes/pi-packages/blob/main/packages/pi-permission-system/docs/configuration.md), [subagent integration](https://github.com/gotgenes/pi-packages/blob/main/packages/pi-permission-system/docs/subagent-integration.md), [npm 41.0.0](https://www.npmjs.com/package/@gotgenes/pi-permission-system/v/41.0.0).

Sources below refer to the **published 41.0.0 tarball**, whose [release tag](https://github.com/gotgenes/pi-packages/tree/pi-permission-system-v41.0.0/packages/pi-permission-system) points to commit `8b1c15ce001430b00767a3641aa8e29bf04375df`; links to individual first-party repository files on `main` may move. This is source inspection, not an execution test.

## Config locations and schema

Global `$PI_CODING_AGENT_DIR/extensions/pi-permission-system/config.json` (default agent directory `~/.pi/agent`); project `<cwd>/.pi/extensions/pi-permission-system/config.json`. Project agent frontmatter is `<cwd>/.pi/agents/<agent>.md`, global is `<agentDir>/agents/<agent>.md`. Legacy `agentDir/pi-permissions.jsonc` and `<cwd>/.pi/agent/pi-permissions.jsonc` (plus legacy extension-root `config.json` if different) are loaded before modern scopes, with deprecation warnings; only **flat unified-format** content is understood, not translated old keys. [Config paths](https://github.com/gotgenes/pi-packages/blob/main/packages/pi-permission-system/src/config/config-paths.ts), [configuration § locations](https://github.com/gotgenes/pi-packages/blob/main/packages/pi-permission-system/docs/configuration.md#config-file-locations).

Strict JSON top-level schema (all optional): `$schema`, `debugLog`, `permissionReviewLog`, `yoloMode`, `doublePressToConfirm`, `permissionDialogKeys` (approve/approveSession/approveSessionBoth/deny/denyWithReason strings), `promptNotifications` (`bell`, `osc9`, `osc777`), `forwardingTimeoutMs`, `promptTimeoutMs`, `promptMaxRows`, `promptFieldMaxWidth`, `reviewLogFieldMaxWidth`, deprecated ignored `toolInputPreviewMaxLength` and `toolTextSummaryMaxLength`, `piInfrastructureReadPaths` (string array), `authorizerChain` (string array), `permission`, `shellTools`, `commandEffects`. `permission` maps `*`, `path[_read|_write]`, `external_directory[_read|_write]`, `bash`, `mcp`, `skill`, or registered tool names to an `allow`/`ask`/`deny` string or pattern-to-decision map. Pattern value can also be `{ "action": "deny", "reason": "..." }` (max 500 characters). `shellTools` maps name to `{commandArgument, workdirArgument?}`; `commandEffects` maps bare executable name to `{effects?: "read"|"write"|array, unlessOption?: string[], subcommands?: map}`. Runtime rejects unknown top-level keys. Example is [config.example.json](https://github.com/gotgenes/pi-packages/blob/main/packages/pi-permission-system/config/config.example.json); authoritative [Zod source](https://github.com/gotgenes/pi-packages/blob/main/packages/pi-permission-system/src/config/config-schema.ts) and [generated JSON Schema](https://github.com/gotgenes/pi-packages/blob/main/packages/pi-permission-system/schemas/permissions.schema.json). The loader strips `//` and `/* */` comments before JSON.parse, so JSON with comments **is** accepted, but trailing commas are not. [Actual loader](https://github.com/gotgenes/pi-packages/blob/pi-permission-system-v41.0.0/packages/pi-permission-system/src/config/config-loader.ts). Legacy paths are read as flat unified config with warnings, not translated from older legacy-format keys. [Load-and-merge code](https://github.com/gotgenes/pi-packages/blob/pi-permission-system-v41.0.0/packages/pi-permission-system/src/config/config-loader.ts). [Configuration § full example](https://github.com/gotgenes/pi-packages/blob/main/packages/pi-permission-system/docs/configuration.md#full-example).

## Tool, path, and bash matching

Patterns use `*` (zero or more characters **including slashes**) and `?` (one character), NOT segment globbing; `**` has no special meaning. A map's **last matching pattern wins**; a surface-specific match beats the universal fallback. File tools match path input and normalized/canonical forms; symlinks are considered. Bash patterns match command text per parsed unit; each unit's last matching rule wins, and the full call uses most-restrictive-wins (`deny > ask > allow`). `&&`, `||`, `;`, `|`, `&`, newline split units; substitutions/process substitutions/subshells are descended into; redirects are separately path-gated (output vs input directions). **Correction to the published prose:** although configuration.md says control-flow and brace-group bodies are not descended into, the 41.0.0 [command enumerator](https://github.com/gotgenes/pi-packages/blob/pi-permission-system-v41.0.0/packages/pi-permission-system/src/access-intent/bash/command-enumeration.ts) emits compound statements **whole and descends into their statement children** (while also retaining whole-statement matches). Do not rely on either wording as proof of complete shell coverage without tests. Leading env assignments are stripped; pattern `"git *"` also matches bare `git`. `~`, `$HOME`, `${HOME}` prefixes can expand. Literal `cd` affects resolved cwd; computed `cd` cannot be reliably projected. [Configuration § bash](https://github.com/gotgenes/pi-packages/blob/main/packages/pi-permission-system/docs/configuration.md#bash-surface), [§ paths](https://github.com/gotgenes/pi-packages/blob/main/packages/pi-permission-system/docs/configuration.md#path-surface), [§ directional paths](https://github.com/gotgenes/pi-packages/blob/main/packages/pi-permission-system/docs/configuration.md#directional-path-surfaces).

Opaque `sh/bash/... -c` and `eval` and indirection wrappers (`sudo`, `env`, `xargs`, `find -exec`, etc.) floor `allow` to `ask` unless a documented exemption applies (pure-reader inner command, certain execution modifiers such as `time`, or bare no-command `env`); explicit `deny` remains. Some inner shell payloads are opaque; do not mistake this for full shell interpretation. Parse failure/partial unresolved trees floor to `ask` unless a matching `deny` applies; internal gate errors block. [Configuration § fail-closed](https://github.com/gotgenes/pi-packages/blob/main/packages/pi-permission-system/docs/configuration.md#fail-closed-behavior), [§ wrapper transparency](https://github.com/gotgenes/pi-packages/blob/main/packages/pi-permission-system/docs/configuration.md#wrapper-transparency).

There is **no Git-specific `push` safety parser** in the [bash rule evaluator](https://github.com/gotgenes/pi-packages/blob/pi-permission-system-v41.0.0/packages/pi-permission-system/src/handlers/gates/bash-command.ts); matching uses the [anchored wildcard regex](https://github.com/gotgenes/pi-packages/blob/pi-permission-system-v41.0.0/packages/pi-permission-system/src/policy/wildcard-matcher.ts), and `commandEffects` controls **file-path direction**, not Git remote effects. Exact patterns can distinguish spelled text (`"git push"` vs `"git push --force"`, `"git push origin +main"`, `"git push --delete"`, `"git push --mirror"`), but a broad `"git push *": "allow"` also matches all of those; ordering an incomplete list of explicit asks after a broad allow is not an exhaustive guarantee. Git global options `git -C /other push`, `git -c alias.foo=... push` are **different command strings** from `git push` and `commandEffects` subcommand declarations likewise do not skip options. Shell aliases/functions, Git aliases, hooks, config, and remote behavior are not validated as Git operations; use of a bare `git push` does not prove safety. This is an inference from the published matcher and [declaration behavior](https://github.com/gotgenes/pi-packages/blob/main/packages/pi-permission-system/docs/configuration.md#declaring-your-own-commands-commandeffects), not a tested exhaustiveness theorem.

## Default decision and policy goals

Omitted `permission["*"]` means **ask**. `external_directory` gates outside **session cwd** (canonical paths), not an identified Git working tree: when cwd equals the repository root this approximates the requested boundary, but launching Pi in a subdirectory or above the repo changes it. Bash path extraction is heuristic (unresolved variables, glob expansions, and other cases may not be gated). A policy `path: {"*":"allow", "*.env":"deny", "*.env.*":"deny", "*.env.example":"allow"}` is the documented last-match exception; consider directional `path_read` vs `path_write`. Pi infrastructure reads may auto-bypass the outside-cwd gate unless a targeted external-directory deny is given. [Configuration § universal fallback](https://github.com/gotgenes/pi-packages/blob/main/packages/pi-permission-system/docs/configuration.md#permission--universal-fallback), [§ external directory](https://github.com/gotgenes/pi-packages/blob/main/packages/pi-permission-system/docs/configuration.md#external_directory-surface), [§ .env](https://github.com/gotgenes/pi-packages/blob/main/packages/pi-permission-system/docs/configuration.md#env-recipe), [§ infrastructure](https://github.com/gotgenes/pi-packages/blob/main/packages/pi-permission-system/docs/configuration.md#pi-infrastructure-read-auto-allow).

A `path_write` deny aimed at the global policy file and at project/agent definitions can gate **direct Pi `write`/`edit` and literal bash redirect targets**; `path_read` and `path_write` must be chosen separately if agent reads remain desirable. But project/agent override rules can loosen that global deny; and opaque bash, computed destinations, scripts and extension code are not a sandbox. The package exposes no dedicated immutable-policy-file protection in the [configuration schema](https://github.com/gotgenes/pi-packages/blob/pi-permission-system-v41.0.0/packages/pi-permission-system/src/config/config-schema.ts). Bash `cp`/`mv`/`tee` path operands do not establish a proven write direction (unknown paths consult both surfaces, so a `path_write` deny **may** still catch a visible operand); no guarantee is made for indirect or unprojected destinations. [Directional path docs](https://github.com/gotgenes/pi-packages/blob/main/packages/pi-permission-system/docs/configuration.md#which-direction-is-a-given-access), [bash path projection limits](https://github.com/gotgenes/pi-packages/blob/main/packages/pi-permission-system/docs/configuration.md#external_directory-surface). Open [#968](https://github.com/gotgenes/pi-packages/issues/968) documents brace-expansion traversal not projected; open [#1083](https://github.com/gotgenes/pi-packages/issues/1083) reports computed cwd/path problems in 41.0.0. Reports [#1070](https://github.com/gotgenes/pi-packages/issues/1070)/[#1071](https://github.com/gotgenes/pi-packages/issues/1071) describe a different `engine.cjs` prefix matcher, **not the wildcard-matcher.ts published in the 41.0.0 tarball**; do not extrapolate their exact reproduction to this release.

## Precedence and self-protection

Precedence: global config → project config → global agent frontmatter → project agent frontmatter. Permission maps shallow-merge when both are objects; later patterns can win, or a later scalar replaces a surface. Project configs and project agents load **only if Pi trusts the project**. Invalid higher scopes clamp inherited `allow` to `ask` (not inherited `deny`); `yoloMode` can re-allow asks. This is not an unoverrideable global deny, particularly in a trusted project. [Configuration § merge precedence](https://github.com/gotgenes/pi-packages/blob/main/packages/pi-permission-system/docs/configuration.md#merge-precedence).

## Subagents and noninteractive `ask`

[Authorizer selection](https://github.com/gotgenes/pi-packages/blob/pi-permission-system-v41.0.0/packages/pi-permission-system/src/authority/authorizer.ts) chooses local UI when `ctx.hasUI` and no live relay target, parent relay for detected child without UI, otherwise a [denying authorizer](https://github.com/gotgenes/pi-packages/blob/pi-permission-system-v41.0.0/packages/pi-permission-system/src/authority/denying-authorizer.ts). Therefore normal headless/print-mode **without a serving parent or explicitly configured authority link** denies an `ask`; this is inference from `ctx.hasUI` selection, not a test of every Pi mode. If forwarded approval is unavailable, it denies with a reason; default forwarding wait is 600000 ms, but a non-draining parent can fast-fail in ~2 seconds; `promptTimeoutMs` is optional, unset prompts wait indefinitely when UI is present. `yoloMode: true` auto-approves asks (including parse/wrapper floors), but not explicit denies. [Configuration § unanswered prompts](https://github.com/gotgenes/pi-packages/blob/main/packages/pi-permission-system/docs/configuration.md#unanswered-prompts), [subagent integration § when nobody answers](https://github.com/gotgenes/pi-packages/blob/main/packages/pi-permission-system/docs/subagent-integration.md#when-nobody-answers). Background children can forward only if they implement the announcement convention, load the guard and have a serving parent; do not presume unattended approval.


Native event-based child integration supports **`@gotgenes/pi-subagents`**; the [compatibility matrix](https://github.com/gotgenes/pi-packages/blob/main/packages/pi-permission-system/docs/subagent-integration.md#compatibility) says upstream `tintinweb/pi-subagents` lacks child lifecycle announcements and thus deterministic in-process child detection / `ask` forwarding. A participating child forwards `ask` to the parent UI, which can grant once, child session or entire session. Child must actually load this extension: otherwise its tools are ungated; the parent may warn when bound event is emitted. [Subagent integration](https://github.com/gotgenes/pi-packages/blob/main/packages/pi-permission-system/docs/subagent-integration.md).

## Compatibility and maintenance

npm 41.0.0: `engines.node >=22`, peer dependencies `@earendil-works/pi-coding-agent >=1.0.0` and `@earendil-works/pi-tui >=1.0.0`. A **1.4.0 release of those exact packages** satisfies the declared peer range; whether the user's pi.dev 1.4.0 environment supplies those package identities and actually runs this extension was **not verified**. Published 2026-10-17 per [npm registry metadata](https://registry.npmjs.org/@gotgenes/pi-permission-system/41.0.0). Monorepo is active (GitHub API `pushed_at` 2026-10-25); open [issues](https://github.com/gotgenes/pi-packages/issues?q=is%3Aissue+is%3Aopen+pi-permission-system) identify unresolved bash/path bypasses and forwarding risks. Do not equate frequent releases with security completeness.
